Обоснование: ROI% когорты whale = **−2.7519** (< 0) — вариант C отпадает. При этом шаг 3 даёт **6** адресов с положительным суммарным resolution PnL, HR > 60% и ≥10 китовых сделок (в т.ч. положительный **roi_pct** по каждому из них в таблице выше). Одновременно trade-level hit rate не используется как главный критерий решения. Вариант A не выбран: при отрицательной когорте есть устойчивая подгруппа smart whales с реальной прибылью по правилам шага 3.

## Рекомендация для продукта

Не трактовать «все сделки ≥$10k» как экономический edge: агрегатный ROI когорты отрицательный из‑за тяжёлых хвостов. Имеет смысл сузить сигнал до **watch-list** по кошелькам из whitelist (или похожего off-line скоринга), а массовые whale alerts оставить информационными без обещания положительного ожидаемого PnL по копированию.

## Ограничения

- Сделки в исследуемой resolved-вселенной с фильтром по объёму синхронизированы в основном с **апреля 2026** (как в Iteration 2); окно `365 days` не добавляет истории, если данных раньше нет.
- Нет out-of-sample валидации и нет кластеризации адресов (один участник — несколько кошельков).
- `volume24hr` — снимок при синке, не на момент сделки.
- Resolution PnL не отражает стоимость капитала, проскальзывание и задержку алерта.
