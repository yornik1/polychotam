# Start Task

## Триггер

Пользователь пишет `start task <notion-url>` или `начни задачу <url>`.

## Сценарий

1. **Fetch задачу из Notion.**
   Вызвать `notion-fetch` по переданному URL. Извлечь: Task, Epic, Notes, Status, Assignee, Priority, Depends on.
   Прочитать тело страницы — найти чеклист DoD (блоки `- [ ]` / `- [x]`).

2. **Проверить зависимости.**
   Если «Depends on» не пустое — для каждой связанной задачи `notion-fetch` и проверить Status = Done.
   Если есть незавершённые — сообщить пользователю и остановиться.

3. **Обновить статус.**
   `notion-update-page`: Status → In Progress.

4. **Обновить `epic-current.mdc`.**
   В файле `.cursor/rules/epic-current.mdc` заменить строку `Задача: ...` на URL текущей задачи.

5. **Загрузить контекст проекта.**
   Прочитать `src/types/contracts.ts` и `docs/PROJECT_STRUCTURE.md`.

6. **Найти спеку (если есть).**
   Поискать в `docs/archive/specs/` файл по текущему эпику. Если нет — пропустить.

7. **Начать TDD по первому незачёркнутому пункту DoD.**
   Из чеклиста выбрать первый `- [ ]` пункт. Написать falling test. Сообщить пользователю.

## После завершения пункта

1. Пометить пункт в Notion: `notion-update-page`, command `update_content`,
   old_str: `- [ ] текст пункта`, new_str: `- [x] текст пункта`.
2. Спросить пользователя: «Пункт X готов. Продолжить со следующим или `check`?»
3. Если «дальше» — перейти к следующему `- [ ]` пункту (шаг 7).
4. Если «check» или «стоп» — остановиться.

## Важно

- Не начинать реализацию без теста.
- Комментарии в коде на русском.
- Типы из `src/types/contracts.ts`, не дублировать.
- Коммит-сообщение формировать из Notes задачи.
