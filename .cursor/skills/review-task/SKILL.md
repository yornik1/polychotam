# Review Task

## Триггер

Пользователь пишет `review task` или `ревью`.

## Сценарий

1. **Найти текущую задачу.**
   В Notion-доске найти задачу со Status = In Progress. Вызвать `notion-fetch` — получить Notes (DoD), Task (название).

2. **Показать изменения.**
   Запустить `git diff --stat` и `git diff` (staged + unstaged). Показать краткую сводку: какие файлы изменены, сколько строк.

3. **Автоматические проверки.**
   Запустить параллельно:
   - `npm run lint`
   - `npm run test`
   - `npm run build`
   Показать результат каждой.

4. **Проверка качества кода.**
   По diff проверить:
   - Нет `any` в TypeScript
   - Нет `console.log` (только NestJS `Logger`)
   - Комментарии на русском
   - Типы из `src/types/contracts.ts` (не дублированы локально)
   Вывести краткий отчёт: что проверено, что найдено.

5. **Предложить коммит.**
   Сформировать коммит-сообщение на основе Notes задачи и названия.
   Показать пользователю и спросить подтверждение.

6. **Выполнить коммит.**
   После подтверждения:
   - `git add -p` или `git add` нужных файлов
   - `git commit` с согласованным сообщением

7. **Обновить Notion.**
   Через `notion-update-page` установить:
   - Status → Done
   - Phase → Deploy

8. **Предложить следующий шаг.**
   Сообщить что задача завершена. Предложить перейти к следующей задаче или деплою.

## Важно

- Не коммитить без подтверждения пользователя.
- Не коммитить файлы с секретами (.env, credentials).
- Если lint/test/build падают — показать ошибки и предложить `fix`.
- Если есть замечания по качеству кода — сформулировать список и предложить `fix`.
