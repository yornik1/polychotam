# Review Task

## Триггер

Пользователь пишет `review task` или `ревью`.

## Сценарий

1. **Найти текущую задачу.**
   Прочитать URL задачи из `.cursor/rules/epic-current.mdc`.
   Вызвать `notion-fetch` — получить Notes, Task (название).

2. **Показать изменения.**
   `git diff --stat` и `git diff`. Краткая сводка: файлы, строки.

3. **Автоматические проверки.**
   Параллельно: `npm run lint`, `npm run test`, `npm run build`. Показать результат.

4. **Проверка качества кода.**
   По diff проверить:
   - Нет `any` в TypeScript
   - Нет `console.log` (только NestJS `Logger`)
   - Комментарии на русском
   - Типы из `src/types/contracts.ts` (не дублированы локально)

5. **Предложить коммит.**
   Коммит-сообщение из Notes задачи. Показать и спросить подтверждение.

6. **Выполнить коммит.**
   После подтверждения: `git add` + `git commit`.

7. **Обновить Notion.**
   `notion-update-page`: Status → Review.

8. **Предложить следующий шаг.**
   Задача отправлена на ревью. Предложить следующую задачу.

## Важно

- Не коммитить без подтверждения пользователя.
- Не коммитить .env, credentials.
- Если lint/test/build падают → предложить `fix`.
