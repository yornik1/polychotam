# Debug

## Триггер

Явные команды: `debug`, `почему падает`, `почему не работает`.

Без команды — также включается, если пользователь пишет «упало», «падает», «ошибка», «не понимаю почему» (см. `## Teach mode` в `CLAUDE.md`, маппинг намерений).

## Главный принцип

Сначала факты, потом гипотеза, потом правка. Не угадывать, не править «на всякий случай», не делать рефактор по дороге.

## Сценарий

### 1. Локализовать слой

Спросить себя (и при необходимости пользователя) одной строкой: где упало?

- **Тесты** — `npm run test` / `npm run test:watch`.
- **Билд** — `npm run typecheck` / `npm run build`.
- **Рантайм app** — стартовало ли приложение, отвечают ли HTTP/WS.
- **Очереди (BullMQ)** — джобы стоят / падают / зацикливаются.
- **БД (Postgres)** — миграции, типы колонок, данные.
- **Redis / BullMQ-ключи** — состояние очередей низкого уровня.
- **WebSocket Polymarket** — handshake, переподписка, парсинг payload.

### 2. Команды первого взгляда (по слою)

**Тесты упали:**

```bash
npm run test -- путь/к/файл.spec.ts -t "имя теста"
```

**Билд / типы:**

```bash
npm run typecheck    # быстрая проверка без сборки
npm run build        # полная сборка
```

**Рантайм app:**

```bash
docker compose logs -f --tail 200 app
```

Помнить: в [src/main.ts](src/main.ts) стоит `logger: ["error"]` — info/warn подавлены. Пустые логи ≠ «всё ок».

**Очереди (главный инструмент):**

- Bull Board UI: http://localhost:3000/queues — состояние очередей `trades`, `trade-enrichment`, `wallet-analytics`, payload джобов, stack trace.
- NDJSON ошибок: `tail -n 50 logs/bull-job-errors.ndjson | jq .`
- BullMQ-ключи в Redis: `docker compose exec redis redis-cli KEYS "bull:*"`

**Postgres:**

```bash
docker compose exec postgres psql -U postgres -d polychotam
\dt                           # таблицы
\d markets                    # схема таблицы
SELECT * FROM markets LIMIT 5;
```

**Redis:**

```bash
docker compose exec redis redis-cli
KEYS "bull:trades:*"
LRANGE "bull:trades:wait" 0 -1
```

**WebSocket Polymarket:**

- Проверить `POLYMARKET_WS_URL` в `.env` — должен быть `wss://ws-subscriptions-clob.polymarket.com/ws/market`.
- Глянуть `src/polymarket/polymarket-ws.client.ts` — там логика handshake и переподписки.

### 3. Сформулировать гипотезу

В 1–2 предложениях, **до** правок. Например:

> «Упал тест `trade-enrichment.processor.spec.ts > enrich`, потому что мок HTTP-клиента не возвращает `condition_id`. Скорее всего сломали маппер или контракт изменился.»

Если гипотез несколько — выбрать самую вероятную и проверить её первой.

### 4. Минимальный фикс с тестом

- Сначала тест, который **воспроизводит** проблему (если его не было) — TDD-стиль.
- Минимальная правка — без рефактора, без переписывания работающего кода.
- Прогнать `npm run test` локально на этом файле, потом весь.

### 5. Обучающий блок (Teach mode)

После фикса:

1. CODE REFERENCE на изменённые строки.
2. 3–5 предложений: что было не так, какой NestJS/TS-паттерн чинит это правильно, почему именно так (и почему альтернатива хуже).
3. Один короткий вопрос на проверку понимания.
4. Дождаться ответа.

Цель — чтобы такая же ошибка не повторилась в другом модуле.

## Известные грабли (проверять в первую очередь)

- **`POLYMARKET_WS_URL`** — `wss://ws-subscriptions-clob.polymarket.com/ws/market`, не `wss://clob.polymarket.com/ws/market` (последний → 404 при handshake).
- **`logger: ["error"]`** в [src/main.ts](src/main.ts) — info/warn от Nest подавлены. Если в логах пусто, временно поменять на `logger: ["log", "warn", "error"]` для дебага.
- **Миграции** — только через `npm run migration:run` (он сам собирает проект). Не вызывать `typeorm` напрямую.
- **BullMQ «тихий return»** — процессор, который вернул значение без `throw`, не даёт события `failed`. Ошибки логируются вручную через [BullJobNdjsonLogService](src/queue/bull-job-ndjson-log.service.ts). Смотреть NDJSON, а не только Bull Board «failed»-вкладку.
- **`condition_id` vs `market_slug` vs `asset_id`** — это разные идентификаторы Polymarket. Если запрос пустой, сначала проверить, что используется правильный ID для конкретного эндпоинта.
- **Telegram дедуп** — при тестах алертов учесть `ALERT_DEDUP_TTL_MS` (по умолчанию 3 минуты).

## Эскалация

Если после двух гипотез проблема не локализована — это сигнал к Escalation в твоём [SDLC Process](https://www.notion.so/33b7b5e2ccce81dc99f4fbc3f765b6dd) (Opus в Cursor Composer). Зафиксировать в чате:

- Что пробовали (команды и их вывод).
- Какие гипотезы отбросили и почему.
- Где сейчас стоп.

## Важно

- Никогда не править «на всякий случай» — только по подтверждённой гипотезе.
- Не глушить ошибки `try/catch` без явного смысла.
- Не отключать тесты, чтобы «зелёные» — это не дебаг, это саботаж.
- Комментарии в коде на русском.
