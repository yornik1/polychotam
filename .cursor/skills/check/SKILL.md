# Check

## Триггер

Пользователь пишет `check` или `проверь`.

## Сценарий

1. **Найти текущую задачу.**
   Прочитать URL задачи из `.cursor/rules/epic-current.mdc`.
   Вызвать `notion-fetch` — получить тело страницы с чеклистом DoD.

2. **Собрать проект.**
   `npm run build`. Если ошибки — показать и остановиться.

3. **Прогнать тесты.**
   `npm run test`. Показать результат.

4. **Запустить сервисы.**
   `docker compose ps`. Если не запущены — `docker compose up -d`.
   `npm run start:dev` в фоне (block_until_ms: 0). Дождаться «Application is running».

5. **Проверить каждый помеченный пункт DoD.**
   Пройти по всем `- [x]` пунктам. Для каждого:
   - HTTP-проверка → curl, показать результат.
   - Проверка файла → убедиться что файл существует и содержит нужное.
   - Проверка БД → запрос через TypeORM или psql.
   - Браузер → сообщить пользователю URL и что должно быть видно.

6. **Вывести чеклист.**
   Показать DoD с результатами:
   - [x] Прошло / [?] Требует ручной проверки / [ ] Не прошло
   Для каждого пункта — краткое пояснение.

7. **Предложить следующий шаг.**
   Всё ок → предложить `review task`. Есть проблемы → предложить исправления.

## Важно

- Не убивать dev-сервер после проверки.
- Показывать реальный вывод команд.
- Если DoD неоднозначный — уточнить у пользователя.
