# Check

## Триггер

Пользователь пишет `check` или `проверь`.

## Сценарий

1. **Найти текущую задачу.**
   В Notion-доске (URL из `epic-current.mdc`) найти задачу со Status = In Progress. Вызвать `notion-fetch` — получить Notes (DoD).

2. **Собрать проект.**
   Запустить `npm run build`. Если ошибки — показать и остановиться.

3. **Прогнать тесты.**
   Запустить `npm run test`. Показать результат. Если есть падения — показать какие.

4. **Запустить сервисы.**
   Проверить что Docker запущен: `docker compose ps`. Если контейнеры не поднялись — `docker compose up -d`.
   Запустить `npm run start:dev` в фоне (block_until_ms: 0). Дождаться строки «Application is running» в логах.

5. **Выполнить проверки из DoD.**
   Разобрать текст Notes на отдельные проверки. Для каждой:
   - Если это HTTP-проверка — выполнить curl и показать результат.
   - Если это проверка логов — прочитать вывод терминала.
   - Если нужен браузер — сообщить пользователю: какой URL открыть, что ввести, что должно быть видно.
   - Если нужны креды или данные — попросить у пользователя.

6. **Вывести чеклист.**
   Показать DoD как чеклист с галочками:
   - [x] Прошло / [?] Требует ручной проверки / [ ] Не прошло
   Для каждого пункта — краткое пояснение результата.

7. **Предложить следующий шаг.**
   Если всё ок — предложить `review task`. Если есть проблемы — предложить исправления.

## Важно

- Не убивать dev-сервер после проверки — пользователь может захотеть посмотреть сам.
- Показывать реальный вывод команд, не пересказывать.
- Если DoD неоднозначный — уточнить у пользователя.
