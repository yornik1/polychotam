# LLM Council

Перед сложными архитектурными или продуктовыми решениями по Polychotam — опросить ChatGPT и Gemini, синтезировать план с учётом контекста проекта.

## Триггер

- «совет совета: …»
- «consult the council: …»
- «спроси ChatGPT и Gemini …»
- «мнение других моделей о …»
- «llm council …»

## Контекст Polychotam

Перед запросом к внешним моделям собрать релевантный контекст:

1. Прочитать `docs/PROJECT_STRUCTURE.md`, если вопрос про архитектуру или модули.
2. Проверить `src/types/contracts.ts`, если вопрос про типы или контракты.
3. При необходимости — затронутые файлы/модули из текущей задачи.

Промпт для council должен включать:
- формулировку вопроса пользователя;
- стек: NestJS, TypeScript, PostgreSQL + TypeORM, Redis + BullMQ, Telegram, WebSocket;
- ограничения: модульная изоляция, `ConfigService` для env, типы из `contracts.ts`, TDD.

## Процесс

1. **Сформировать промпт** — вопрос + контекст Polychotam (см. выше).
2. **Запустить скрипт** из корня репозитория:

```bash
python3 .cursor/skills/llm-council/scripts/query_llms.py "ВОПРОС С КОНТЕКСТОМ"
```

3. **Разобрать JSON** — ответы ChatGPT и Gemini, источник (CLI или API), ошибки.
4. **Синтез** — свой анализ + лучшие идеи council; отметить расхождения и риски для Polychotam.
5. **Выдать план** — конкретные шаги (модули, файлы, тесты), не абстрактную теорию.

## Настройка

Ключи — в `.env` в корне репозитория (файл в `.gitignore`):

```
OPENAI_API_KEY=sk-...
GEMINI_API_KEY=...

# опционально
OPENAI_MODEL=gpt-5-nano
GEMINI_MODEL=gemini-3-flash-preview
```

Приоритет: CLI (`codex`, `gemini`) → API. Подробнее: [references/setup.md](references/setup.md).

Если ключей нет — сообщить пользователю и предложить setup; можно дать только свой анализ без council.

## Формат ответа

```markdown
## Рекомендация

[План с inline-ссылками на идеи моделей]

## Вклад моделей
- ChatGPT: …
- Gemini: …
- Cursor (синтез): …

## Следующий шаг
[Конкретное действие: TDD, модуль, миграция и т.д.]
```

## Ошибки

- Нет ключей / CLI — указать, что недоступно; продолжить с доступными ответами.
- Оба API упали — только анализ Cursor + предложить повторить позже.
- Таймаут 60 с на CLI, 30 с на API — зафиксировать в ответе.
