# Fix

## Триггер

Пользователь пишет `fix` или `исправь`.

## Сценарий

1. **Собрать замечания.**
   Взять список из текущего контекста чата. Если пользователь указал Notion-ссылку — `notion-fetch`.

2. **Исправить по списку.**
   Для каждого замечания:
   - Прочитать файл
   - Минимальные правки (не переписывать то, что работает)
   - Комментарии на русском

3. **Проверить.**
   `npm run test` и `npm run lint`. Показать результат.

4. **Предложить следующий шаг.**
   Тесты и линт зелёные → предложить `check`. Ошибки → показать и предложить доправить.

### Teach mode

После каждого исправленного замечания — короткий обучающий блок (формат — см. `## Teach mode (default on)` в [CLAUDE.md](../../../CLAUDE.md)):

1. CODE REFERENCE на изменённые строки.
2. 3–5 предложений: что было не так, какой NestJS/TS-паттерн чинит правильно, почему так, чем плоха альтернатива.
3. Один короткий вопрос на проверку понимания.
4. Дождаться «ок» — потом следующее замечание.

Если правка тривиальна (typo, переименование) — обучающий блок пропустить.

## Важно

- Не выходить за рамки списка замечаний.
- Не рефакторить код, который не упомянут.
- Если замечание непонятно — уточнить, не додумывать.
- Архитектурные изменения → эскалация на Opus.
