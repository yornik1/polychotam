# Test Review

Использовать, когда пользователь пишет `$test-review` или спрашивает, достаточно ли хороши тесты.

## Review Checklist

- Каждый тест доказывает user-visible или бизнес-важное поведение?
- Тест упадёт, если фичу/фикс удалить?
- Моки стоят только на реальных границах, а не проверяют “моки против моков”?
- Happy path, edge case и error path покрыты там, где риск это оправдывает?
- Fixtures похожи на реальные Polymarket/Telegram/queue payloads?
- Названия тестов понятны без знания реализации?
- Coverage показывает важные gaps, а не просто “процент ради процента”?

## Output Shape

Сначала findings по важности. Для каждого finding:

- file/line, если доступно;
- какое поведение не доказано;
- самый маленький полезный test improvement.

Если тесты достаточно хорошие — сказать это прямо и назвать остаточный риск.
